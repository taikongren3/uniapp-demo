# 领域文档

本仓库使用单上下文领域文档布局。

## 开始探索前先阅读

- 仓库根目录的 **`CONTEXT.md`**。
- **`docs/adr/`**：阅读与即将处理区域相关的 ADR。

如果这些文件不存在，**直接继续，不要提示**。不要报告文件缺失，也不要预先建议创建。`/domain-modeling` 技能会在术语或决策得到确认时按需创建它们。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用术语表中的词汇

在 Issue 标题、重构建议、假设或测试名称中提及领域概念时，应使用 `CONTEXT.md` 中定义的术语。不要改用术语表明确排除的同义词。

如果术语表中没有所需概念，应重新考虑该术语是否属于本项目，或记录这一缺口并交由 `/domain-modeling` 处理。

## 标记与 ADR 的冲突

如果输出与现有 ADR 冲突，应明确指出，而不是静默覆盖：

> _与 ADR-0007 冲突，但值得重新讨论，因为……_
