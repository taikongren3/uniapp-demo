# Vue 组件规范

对任务范围内的所有 `.vue` 文件应用以下规则。在优化组件结构的同时，保持组件行为和公开契约不变。

## 执行流程

1. 编辑前检查相邻组件和仓库目录结构。优先遵循项目现有约定，再使用本技能提供的默认路径。
2. 判断用户要求的是实现还是审查。仅要求审查时，只报告违规项，不修改文件。
3. 控制改动范围。整理本次实际修改的组件，不批量格式化无关组件。
4. 按照以下规则提取重复样式和复杂脚本逻辑。
5. 运行仓库已有的相关测试、类型检查和 lint。无法运行或缺少某项检查时，明确说明。

## 统一 Vue 区块顺序

按照以下顺序排列实际存在的区块：

```vue
<template>
  <!-- 模板 -->
</template>

<script setup lang="ts">
// 组件逻辑
</script>

<style scoped lang="scss">
/* 组件样式 */
</style>
```

- 将 `template` 放在最上方，`script` 放在中间，`style` 放在最下方。
- 组件不需要某个区块时直接省略，不要为了满足顺序而添加空区块。
- 普通 Vue 3 组件使用 `<script setup lang="ts">`，除非仓库约定或框架集成要求采用其他形式。
- 普通页面和组件使用 `<style scoped lang="scss">`。
- 应用根组件、全局主题、reset、变量和 mixin 文件可以使用非 scoped 样式。真正的全局规则应放入全局样式文件，不要随意移除普通组件的 `scoped`。

## 提取重复 SCSS

同一语义的规则或声明组合至少出现两次时进行提取。不要把含义不同、仅写法碰巧相同的样式强行抽象到一起。

- 同一组件内出现重复时，优先合并选择器；能够提升表达清晰度时，再创建局部 mixin。
- 将颜色、间距、字号等共享设计值移入项目的 token 或变量文件。当前 uni-app 仓库没有更具体约定时，使用 `src/uni.scss`。
- 将可复用的声明组合移入项目的共享 mixin 文件。项目没有相关约定时，使用 `src/styles/_mixins.scss`。
- 重复内容同时包含 UI 结构和行为时，优先提取共享 Vue 组件，不要使用全局 CSS 类模拟组件复用。
- 按用途命名提取后的变量和 mixin，不要按当前字面值命名。
- 将一次性且只与当前组件相关的样式保留在组件内。

## 提取复杂脚本逻辑

根据职责数量和耦合程度判断复杂度，不使用固定行数作为唯一标准。

- 将可复用且包含响应式状态的行为移入 `composables/useXxx.ts`。
- 将 API 请求、持久化和平台集成移入仓库的服务层，例如 `services/`。
- 将纯计算、解析、格式化和数据转换移入 `utils/`。
- 将简短且只服务当前组件的事件处理和流程编排保留为组件内具名函数。
- 组件同时承担多个业务流程、包含深层分支、混合 UI 编排与基础设施逻辑，或逻辑难以独立理解和测试时，必须进行提取。
- 避免为未来需求提前抽象。让每个提取后的模块只承担一个完整职责，并提供小而明确的接口。

## 保持行为不变

除非任务明确要求变更，否则保持以下契约不变：

- props 及其默认值
- emits 及其事件参数
- slots
- 对外暴露的方法和 refs
- 路由行为
- uni-app 和其他平台 API 行为
- 加载、错误和空状态

完成提取后，删除无效导入和死代码，并运行仓库已有的相关测试、类型检查与 lint。
